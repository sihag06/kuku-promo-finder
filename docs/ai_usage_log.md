# AI usage log

Kept live while building. Feeds the "tools used + one place they got it wrong" part of the solution doc.

| Date | Tool | Used for | What it got wrong | How it was caught / fixed |
|---|---|---|---|---|
| 2026-11-07 | Claude | Dataset stats for the architecture doc | Reported 4,077 timed blocks; the real count is 3,727 (1,754 camera + 1,487 dialogue + 372 action + 114 SFX). | Parser recount in step 1; doc corrected. |
| 2026-11-07 | Claude | Writing the parser regex | Label pattern missed `**CAMERA**:` (colon outside the asterisks), silently turning a camera block into stray text. | Synthetic test fixture failed; regex fixed; test kept. |
| 2026-11-07 | Claude | LLM client cost tracking | Rounded per-task cost to 4 decimals, so a cheap call ($0.00014) showed as $0.0001: small-model costs would be under-reported. | Unit test with known token counts failed; now 6 decimals. |
| 2026-11-07 | Claude + web search | Picking GPT model names | Model names/prices came from a third-party pricing page, not OpenAI. Treated as unverified. | Added `python -m promo_finder.llm.client --check` to confirm models on the real account. |
| 2026-11-07 | Claude | Labelling template for the human gold set | First draft used a real Ep 1 promo as the example row, and Ep 1 promos had already been shown in chat: this would have biased the "blind" human labels. | Spotted on review; example replaced with a made-up one, Ep 1 dropped from the labelling set. |
| 2026-11-07 | Claude | Rule-based alias merging (show bible, mock mode) | Stripped titles too eagerly: merged LORD HALDEN and LADY HALDEN (two people sharing a surname) into one character. | Caught by reading the bible output; now merges only into a bare name that the script also uses. Test added. |
| 2026-11-07 | Claude | LLM client caching | Cached mock (rule-based) answers too, so after fixing a rule the tool silently served the old result. | Noticed when a fix "didn't work"; mock answers are no longer cached. Test added. |
| 2026-11-07 | Claude | Signal word-boundary fix | Adding a "no letter before" guard to every pattern silently disabled the "line ends with ?" rule: zero questions were detected as cliffhangers. | Unit test failed; question check moved into code. |
| 2026-11-07 | Claude | De-duplicating promo candidates | First rule treated any two clips with >50% shared footage as duplicates, so a cross-episode promo was dropped for sharing its ending with another clip, though it opened on a different hook (a different ad). | Unit test failed; duplicates now require the same opening AND >50% overlap. |
| 2026-11-07 | Claude | LLM gold script | Wrote the gold builder as a plain loop: 30 slow "thinking" calls ran one after another with no progress output, so a 15-minute run looked frozen. (Caught by Indra.) | Now uses the shared 4-at-a-time runner with a live counter, like the main pipeline. |
| 2026-11-07 | Claude | Free-tier planning | Assumed the Gemini free tier would cover a full run; it caps gemini-3.6-flash at 20 requests/day, and the run died at call 21 (retrying a per-day cap was also pointless). | Daily caps now detected: that model is skipped for the run, fallbacks used, clear message if all are capped. Tool runs on OpenAI; Gemini kept for the independent gold set. |
| 2026-11-07 | Claude | Ranking design | One score mixed "how good is this promo" with "post early episodes first", so strong late-season promos (Ep 33-43) sank to #116-#140 and recall vs the human gold looked worse than the tool's judgement was. | Found in the first real evaluation. Now two orders: quality_rank (quality only) and posting rank (quality + funnel + variety); evaluation reports both. |
| 2026-11-07 | (evaluation finding) | Assembler | 3 of 15 human picks were lost because a strong hook was paired only with a too-early cliffhanger, giving a 12-17s clip that was then rejected. | Short clips now extend to the next unresolved line (question / exclamation / rule cliff) within 20-45s. Checked offline: all 3 missed picks become matches (2 strict). |
| 2026-11-07 | Claude | Scrubbing the show's character names from code before publishing | A blanket rename also changed a schema description that is sent to the model, which would have invalidated every cached answer and forced a paid full rerun. | Caught before shipping by fingerprinting all prompts and schemas against the version used for the live run; that one string was restored. |
| 2026-11-07 | Claude | Candidate selection | De-duplicating before applying quotas silently lost clips that were "duplicates" of a candidate that was itself pruned a step later (the short-clip fix produced 0 new candidates because of it). | Spotted via the eval status "near-duplicate of a better candidate" for a gold promo with no surviving neighbour; now one greedy pass, with a regression test. Also wrote a vacuous test (`or True`) on the first try, replaced with a real one. |
